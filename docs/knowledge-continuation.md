# 知识库长文档解读与恢复

本次修改针对企业知识库的资料解析、图片识别、成对招投标文件解读和向量索引。

## 全文解读

- 移除前 120 片段、7 万字符的截断。按最多 1 万正文字符分批调用模型，大片段继续拆分。
- 每批结果即时保存；页面显示完成批次、覆盖片段和字符数。覆盖率针对已提取的正文，不代表未 OCR 的扫描图片已经解读。
- 确定性汇总与去重保留各批结果，项目基本信息冲突另存，不让第二次模型汇总遗漏末尾内容。
- JSON 无效、调用失败的批次不会计入覆盖率。其他批次继续，点击项目的“补全 / 重试 AI 解读”只补未完成批次。
- 内容、角色、模型或提示版本变化会使旧检查点失效。旧版已完成解读不会冒充全文覆盖，可手动补全。
- 取消操作留下 pending 状态；进程被强制结束时，processing 检查点同样可恢复。
- 原正文分片的 10000 条静默截断也已移除。达到 100000 条的命名空间上限时明确报错，不伪报全文成功。

## 重启恢复

启动时逐企业扫描持久化状态，不再以向量库是否在线作为整个恢复流程的前提：

1. 基础解析未保存正文时重跑本步骤；正文及片段在 78% 检查点原子落库后，继续后续工作，不清空已有图片。
2. 图片识别保留已完成素材，只补剩余素材；总进度包含此前已完成数量。
3. AI 逐批复用检查点。
4. 成对项目按解析、解读、匹配、模板阶段恢复。已完成的基础解析不会重新执行。
5. 本地批量导入恢复未完成文件；向量任务单独恢复。

明确失败的任务保留失败原因，等待用户重试，避免每次重启无限重复调用收费模型。

这套调度适用于当前单进程本地服务，不是多 worker 的分布式任务队列。多实例部署需另加共享租约、心跳和进程间任务所有权。正常重启不要求重新上传，但尚未保存的当前解析步骤／AI 批次可能重新执行。

新增表为 `knowledge_analysis_run`、`knowledge_analysis_batch`、`knowledge_project_workflow`，均随所属资料或项目级联删除。

## 历史页码

在 backend 目录运行：

```powershell
python scripts/repair_knowledge_pages.py
python scripts/repair_knowledge_pages.py --apply
```

可通过 `--company-id` 指定企业。默认只预览。应用修改前自动备份 SQLite 到数据库旁的 `maintenance-backups` 文件夹。

- 从已保存的 PDF 页标记定位片段起始页，保留原文、片段 ID、图片、版本和 AI 结果。
- 重复内容无法唯一定位时清除推测页码；缺少历史页标记的 PDF 会报告需要重新解析。
- Word XML 无法可靠提供物理页码，清除旧的伪页码，继续使用章节定位。
- 有修改时标记向量索引待同步，在下次后端启动时更新索引元数据。无需重新上传或调用 AI。

## 验证

`test_knowledge_continuation.py` 使用临时数据库和模拟模型验证长文档末尾覆盖、超大片段、失败批次重试、重启续跑、并发去重、内容变化失效、解析检查点、项目阶段恢复及页码修复幂等性。前端 `knowledge-analysis-progress.test.mjs` 验证覆盖率、部分失败、旧数据和扫描内容范围提示。
