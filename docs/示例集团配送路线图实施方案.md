# 示例集团配送路线图实施方案

> 本文记录的是早期单车首版。现已新增多网点、多车辆、载重和同日送达时间窗规划；最新操作和限制请参见 [多网点配送规划](./多网点配送规划.md)。

## 业务目标

示例配送公司在投标时需要说明“自有送菜网点如何覆盖本次招标的学校或单位”。公司提供的默认配送中心为“示例市示例区示例路 1 号”；其他送货网点尚未确认，因此系统不编造网点，由用户后续补充。当前招标文件中的学校、医院或其他供货单位作为本次项目需求点，生成可放入标书的配送路线图。

## 首版工作流

1. 在“示例配送公司配送路线图”页面维护自有配送中心和送菜网点。默认预置公司提供的示例路 1 号 配送中心；其他网点按当前登录公司隔离保存，支持新增、编辑和停用。
2. 完成招标文件解读后，点击“从当前招标文件提取位置”。系统从已保存的原文、项目概述和结构化解读字段中识别学校、医院、机关单位名称及附近地址语句，并展示原文依据。
3. 用户逐项核对和补全地址后，选择配送起点；系统将每个需求点归属到地理距离最近的自有配送网点，便于解释“网点覆盖关系”。未能从招标文件确认的地址保持空白，必须由用户补充。
4. 系统按距离生成需求点访问顺序，也可以关闭自动排序后按输入顺序规划。
5. 调用高德地理编码和驾车路线服务，得到道路路线、里程、预计时间和逐段指引。
6. 在页面地图中预览，并下载一张带标题、图例、路线点、里程和预计时间的 PNG 图片用于标书插图。

## 本次实现

### 后端

- `GET/POST/PATCH/DELETE /api/maps/network-points`：维护当前公司的自有配送网点。
- `POST /api/maps/delivery-route`：接收网点、招标需求点、起点、是否自动排序和是否返回起点，返回网点归属、路线、里程、耗时、导航步骤和可下载路线图 SVG。
- `GET /api/maps/tenders/{bid_id}/demand-points`：从已完成解读的招标文件中抽取需求点候选，返回招标原文片段和置信提示，供用户审核。
- 网点表 `map_network_point` 按当前租户业务库创建；MySQL 模式沿用现有数据库适配层，SQLite 历史数据不受影响。
- 路线规划使用最近邻作为首版排序策略，最终道路距离和路线由高德驾车服务计算。

### 前端

- 首页新增“示例集团配送路线图”入口。
- 左侧维护自有网点，右侧录入本次招标学校/单位。
- 支持读取当前项目已解读的招标文件位置候选；提取结果需人工核对，空地址不得直接规划。
- 展示需求点归属关系、路线顺序、地图、总里程和预计时长。
- 支持将路线图下载为 PNG，后续可在图文标书生成页作为插图上传。

## 已知边界

- 首版是单车单路线，不按车辆载重、容积、冷链要求、服务时段自动拆分多车。
- 首版按地理距离做快速排序，没有求解带时间窗和容量约束的车辆路径优化问题。
- 网点和需求点需要先录入准确地址；高德地址解析失败时不会强行生成路线。
- 招标解析中的地点抽取使用现有文本和规则匹配，无法保证识别所有表格/图片/复杂地址，且可能出现候选误报；用户必须依据原文确认地址，系统不把候选直接作为已确认事实。
- 当前下载图片是独立 PNG 文件，插入标书仍可通过现有图文正文的图片上传入口完成。
- 路线图用于投标方案展示，实际配送前仍需结合车辆、道路、交通和时间窗复核。

## 下一阶段建议

1. 从招标文件解析结果中提取学校/单位名称和地址，提供“一键导入需求点”。
2. 增加车辆数量、载重/容积、冷链设备和配送时间窗，按约束拆分路线。
3. 将路线图直接保存为当前标书项目的图文素材，并在生成正文时按章节插入。
4. 支持线路版本保存、重新规划和导出路线说明表。
