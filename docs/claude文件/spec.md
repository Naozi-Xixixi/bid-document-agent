## User Scenarios & Testing *(mandatory)*

### User Roles（用户角色）

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| **投标专员**（主用户） | 食材配送企业负责编制标书的一线人员，业务熟练但非技术人员 | 上传招标文件后，尽快得到一份「图文并茂、逐条响应评分点」的标书初稿，减少通宵改标 |
| **投标经理 / 审核人** | 对标书质量与废标风险负责 | 拿到可量化的审核报告：缺哪些资质、哪些评分点没响应、哪些废标条款有风险 |
| **知识库管理员** | 维护企业资质证书、真实场景图片、历史方案、案例、报价记录 | 资料一次入库、长期复用；新版资料上传后旧版自动失效，不被 AI 误用 |
| **商务/定价负责人** | 决定最终投标报价 | 按时间/区域/平台/业态查看历史报价对比，获得参考报价区间 |
| **系统管理员** | 账号、角色权限、审计日志 | 企业敏感资料受控，导出可追溯 |

### User Story 1 - 招标文件一键解读并生成标书大纲 (Priority: P1)

投标专员把刚拿到的招标文件（PDF/Word/扫描件）上传到系统，系统在十几分钟内输出：资质门槛清单、结构化评分标准表、废标（否决）条款风险清单，并结合企业自身资质给出「满足 / 不满足 / 需补充」的判断；同时自动生成一份逐条对应评分点的标书目录大纲，投标专员可直接在大纲上增删改。

**Why this priority**: 这是整个投标工作的入口。没有准确的评分标准与废标条款提取，后面所有内容生成都失去靶心；且「能不能投、缺什么资质」的判断在投标决策首日就必须给出，本身即可独立交付价值。

**Independent Test**: 只上线本故事即可使用——上传一份真实招标文件，验证输出的资质门槛/评分表/废标清单与人工阅读结论一致，并能导出大纲，即已替代人工「拆标」环节。

**Acceptance Scenarios**:

1. **Given** 一份 120 页含表格的 PDF 招标文件，**When** 投标专员上传并点击「解读」，**Then** 系统在 10 分钟内输出资质门槛清单、评分标准表（评分项/分值/评分细则/原文页码）、废标条款清单，每条均可点击跳转至原文位置。
2. **Given** 招标文件为无文字层的扫描件 PDF，**When** 上传解读，**Then** 系统自动执行 OCR 后完成同样的提取，并在界面提示「本文件经 OCR 识别，建议人工复核关键条款」。
3. **Given** 解读已完成且企业知识库中已录入资质证书，**When** 系统执行投标主体匹配，**Then** 输出每条资格要求的「满足/不满足/需补充」结论，「不满足」项列出缺口说明。
4. **Given** 解读已完成，**When** 投标专员点击「生成大纲」，**Then** 系统输出多级目录大纲，且每个末级节点标注其响应的评分项编号；未被任何大纲节点覆盖的评分项以警示列出。
5. **Given** 系统生成的大纲，**When** 投标专员增加/删除/拖动排序节点并保存，**Then** 修改被保存且可另存为大纲模板供后续项目复用。

### User Story 2 - 企业知识库统一入库与检索复用 (Priority: P1)

知识库管理员一次性把历史标书/方案、资质证书、真实场景图片（冷库、配送车辆、检测现场、仓储分拣）、案例、人员简历、设备清单导入系统并打标签；投标专员在编标时按业态（学校/医院/企业/机关/超市）、关键词、项目类型、年份检索往年方案，一键复用到当前大纲对应章节。

**Why this priority**: 「一次入库、后续 AI 自动调用、无需重复导入」是需求清单明确的基础能力，也是内容生成、智能插图、审核比对的共同数据底座。缺少它，AI 只能凭空编写，无法使用企业真实素材。

**Independent Test**: 只上线本故事即可使用——导入 50 份历史资料并打标签，按「学校 + 冷链配送」检索能命中相关方案并复制其章节文本与图片，即已替代人工翻找旧标书。

**Acceptance Scenarios**:

1. **Given** 管理员选择 30 个文件批量上传，**When** 选择类型并填写标签（业态/区域/年份/项目类型/有效期），**Then** 全部条目入库成功，失败项给出原因且不影响其他条目。
2. **Given** 知识库已有数据，**When** 投标专员输入关键词「冷链配送 学校」检索，**Then** 3 秒内返回按相关度排序的结果，支持按业态/年份二次筛选。
3. **Given** 检索到一份往年方案，**When** 点击「一键复用」并选择目标大纲节点，**Then** 该方案对应章节的文字与图片被插入当前标书对应节点，并保留来源标注。
4. **Given** 生成的标书正文，**When** 查看任一段落的来源，**Then** 可追溯到其引用的知识条目（文件名 + 条目 ID）。

### User Story 3 - 图文并茂的标书正文自动生成 (Priority: P1)

投标专员确认大纲后点击「生成标书」，系统逐节生成正文：逐条响应评分点、自动从知识库匹配真实场景图片插入对应段落、在图片上/旁标注名称与说明（设备名称、证书名称）、把证书按「多列图片 + 下方题注行」的表格样式排版、并根据正文语义自动生成简洁的对比表/进度表/配置表以及流程图、思维导图；最终导出保留样式与目录的 Word 文档。

**Why this priority**: 这是系统的核心产出物，直接决定「AI 自动完成标书全套工作」是否成立。需求文档中两张样例截图（证书题注表格、图片重点标注 + 右侧说明框）均属本故事的验收基准。

**Independent Test**: 只上线本故事即可使用——给定一份大纲与已有知识库，生成一份可直接下载的 Word 标书，其中含插图、图片标注、证书题注表格与对比表格，即已替代人工撰写初稿。

**Acceptance Scenarios**:

1. **Given** 一份已确认的大纲，**When** 点击「生成标书」，**Then** 系统逐节生成正文，每节标注其响应的评分项编号，生成进度实时可见，可暂停/续跑/重生成单节。
2. **Given** 正文中出现「冷链仓储」相关段落，**When** 系统执行智能插图，**Then** 从知识库匹配冷库真实图片插入该段落之后，并生成图注（如「公司自有冷库（-18℃）」）。
3. **Given** 一组资质证书图片，**When** 系统排版证书展示区，**Then** 输出「每行 N 张证书图片 + 紧邻下方题注单元格（如：示例市龙头企业 / 放心消费示范单位 / 企业荣誉）」的表格式版面（与样例截图一致），N 可配置。
4. **Given** 一张需要突出局部的现场图片，**When** 用户或系统添加重点标注，**Then** 支持在图片指定区域绘制红色高亮框，并在图片右侧生成带边框的说明文本框（标题加粗 + 正文说明，与样例截图一致）。
5. **Given** 正文中存在可结构化的对比信息（如「我方承诺 vs 招标要求」「配送时效分档」），**When** 系统执行表格自动生成，**Then** 在该处插入简洁表格，表头与行项来自正文语义，样式取自所选表格模板。
6. **Given** 标书生成完成，**When** 点击「导出 Word」，**Then** 导出的 .docx 保留标题层级、自动目录、页眉页脚、图表编号，图片不失真，在 Microsoft Word 中打开无格式错乱。

### User Story 4 - 标书智能审核与废标风险拦截 (Priority: P1)

投标经理在提交前点击「智能审核」，系统自动检查：资质是否齐全、废标条款是否已规避、评分点是否逐条响应、格式是否规范（字体、页码、目录、签署盖章位、密封要求），输出带严重级别的问题清单，每条可一键跳转到问题位置并给出修改建议。

**Why this priority**: 废标是投标工作最大的单点损失，一处遗漏即前功尽弃。审核能力与生成能力互相独立——即便标书由人工撰写，审核仍可单独产生价值。

**Independent Test**: 只上线本故事即可使用——上传一份人工编写的标书 + 对应招标文件，系统输出问题清单，人工核对确认其命中真实缺陷，即已替代人工交叉复核。

**Acceptance Scenarios**:

1. **Given** 一份标书与其招标文件，**When** 执行智能审核，**Then** 输出问题清单，每条含「严重级别（致命/重要/提示）+ 问题描述 + 定位（章节/页码）+ 原因（引用招标文件原文）+ 修改建议」。
2. **Given** 招标文件要求提供 HACCP 认证但知识库与标书中均无该证书，**When** 执行审核，**Then** 该项以「致命」级别报出「缺失必需资质：HACCP」。
3. **Given** 某评分项在标书中未被任何章节响应，**When** 执行审核，**Then** 报出「评分点未响应」并指出该评分项编号、分值与建议补充位置。
4. **Given** 审核报告，**When** 点击任一问题，**Then** 编辑器跳转至对应正文位置；问题修复后重新审核，该问题不再出现。

### User Story 5 - 已完成标书的无损内容提升 (Priority: P2)

投标专员上传一份已经排好版的成稿标书，系统在**不改动原有格式与标题层级**的前提下，对正文进行润色、内容补充、数据更新与表达优化，并对合同、发票等关键信息进行标注；输出保留原样式的文档与「修订对照视图」。

**Why this priority**: 属于增值优化而非主链路。企业存量标书多，能直接复用；但没有它，主流程（US1–US4）依然完整可用，故列 P2。

**Independent Test**: 上传一份成稿 .docx，输出润色后的 .docx，用比对工具确认标题层级、编号、样式、页面设置未变，仅正文文字变化。

**Acceptance Scenarios**:

1. **Given** 一份成稿 .docx，**When** 执行「无损内容提升」，**Then** 输出文档的标题层级、样式、编号、页眉页脚、页面设置与原文档完全一致，差异仅存在于正文文字内容。
2. **Given** 提升结果，**When** 打开修订对照视图，**Then** 逐处显示「原文 → 建议文」，用户可逐条接受或拒绝。
3. **Given** 文档中含合同、发票等关键信息，**When** 执行关键信息标注，**Then** 系统识别并标注金额、期限、签约主体、发票号等要素。
4. **Given** 需要提供佐证的信用信息、人员证书、体系认证证书与发票/转账证明，**When** 系统处理佐证材料，**Then** 将网上查询截图（信用信息/证书）与税务局联网查询截图（发票转账证明）归档并插入标书对应位置且附题注。

### User Story 6 - 暗标（脱敏标书）生成 (Priority: P2)

某些项目要求技术标匿名评审。投标专员点击「生成暗标」，系统输出图文并茂的暗标版本，自动移除或替换一切可识别投标人身份的信息——不出现「示例公司」字眼，也不出现与示例公司相关联的信息泄漏（品牌名、Logo、水印、网址、人员姓名、可识别地址、图片内文字等），并给出残留风险扫描报告。

**Why this priority**: 只在部分项目中需要，但一旦需要而脱敏不彻底即直接废标，因此必须做、且必须可验证；相对主链路属于 P2。

**Independent Test**: 对一份正常标书执行暗标生成，全文与图片检索企业名称/品牌/Logo，命中数为 0，即通过。

**Acceptance Scenarios**:

1. **Given** 一份含企业名称与 Logo 的标书，**When** 生成暗标，**Then** 输出文档正文、页眉页脚、图注、表格中均无「示例公司」及配置的关联词（企业全称、简称、品牌、母公司、网址、商标）。
2. **Given** 标书中的图片含企业 Logo 或水印，**When** 生成暗标，**Then** 系统识别并处理（遮盖/替换/剔除），并在报告中逐张列出处理方式供人工确认。
3. **Given** 暗标生成完成，**When** 系统执行残留扫描（含图片内文字识别），**Then** 输出残留可识别信息报告；存在残留时以「致命」级别阻断导出，直至人工确认或修复。
4. **Given** 暗标版本，**When** 查看排版，**Then** 图片、表格、图示等图文要素与正常标书同等完整（不因脱敏而丢失图文并茂特性）。

### User Story 7 - 述标/答辩 PPT 自动生成 (Priority: P2)

标书定稿后，投标专员点击「生成答辩 PPT」，系统依据投标方案核心内容自动生成述标/答辩演示文稿，含关键图表、服务亮点、团队介绍，可选模板风格，导出 .pptx。

**Why this priority**: 位于投标流程末端，依赖标书内容存在；但它是评审现场的直接交付物，用户明确要求，故为 P2 中的高位。

**Independent Test**: 基于一份已定稿标书生成 PPT 并导出 .pptx，在 PowerPoint 中打开排版正常、内容与标书一致。

**Acceptance Scenarios**:

1. **Given** 一份定稿标书，**When** 点击「生成答辩 PPT」，**Then** 5 分钟内生成 15–25 页 PPT，覆盖：项目理解、服务方案亮点、关键图表（配送时效/网点分布/质量管控流程）、企业资质与业绩、团队介绍、承诺与结语。
2. **Given** 生成的 PPT，**When** 导出 .pptx，**Then** 在 Microsoft PowerPoint 中打开无排版错乱，图片清晰，文字不溢出版心。
3. **Given** 标书定稿后又有修改，**When** 点击「同步刷新」，**Then** PPT 中引用自标书的内容随之更新，用户自定义修改的页面给出冲突提示而非静默覆盖。
4. **Given** 用户选择不同模板风格，**When** 切换模板，**Then** 内容不变、版式随模板变化。

### User Story 8 - 历史报价多维分析与定价辅助 (Priority: P2)

商务/定价负责人导入或沿用系统内的历史报价数据，按时间、区域、平台、业态（学校/医院/企业等）多维度对比，查看趋势与分布图表，获得当前项目的参考报价区间与依据。

**Why this priority**: 支撑商务决策，与技术标编制解耦，可独立上线；主链路不依赖它。

**Independent Test**: 导入 3 年历史报价数据，按「学校 + 示例 + 2024」筛选，得到对比图表与参考区间。

**Acceptance Scenarios**:

1. **Given** 一份历史报价数据文件（Excel/CSV），**When** 导入，**Then** 系统完成字段映射与校验，列出成功/失败条数及失败原因。
2. **Given** 已有报价数据，**When** 按时间/区域/平台/业态任意组合筛选，**Then** 输出对比图表与统计指标（均价、最高/最低、中标价区间、样本数）。
3. **Given** 当前招标项目，**When** 请求定价辅助，**Then** 系统给出参考报价区间及其依据（所参考的历史项目清单与筛选条件），并明确标注「仅供参考，最终报价由人工决定」。

### User Story 9 - 网点分布图与配送路线规划图生成 (Priority: P2)

投标专员按招标文件对配送范围、时效、网点的要求，让系统生成合理化的网点分布图与车辆配送路线规划图，插入标书对应章节。

**Why this priority**: 是食材配送标书的高分项与差异化内容，但可先以人工绘图替代，故为 P2。

**Independent Test**: 给定招标文件中的配送点位与时效要求，生成一张网点分布图与一张路线图并插入标书。

**Acceptance Scenarios**:

1. **Given** 招标文件中的配送点位、区域与时效要求，**When** 生成网点分布图，**Then** 输出标注了配送中心、网点及服务覆盖范围的图形，含图例与说明。
2. **Given** 网点分布，**When** 生成配送路线规划图，**Then** 输出车辆分组路线图并附路线说明（车辆数、单车服务点数、预计时长），且与标书正文的时效承诺一致。
3. **Given** 生成的图，**When** 插入标书，**Then** 图片带自动编号图注，且在导出的 Word 中清晰可读。

### User Story 10 - 知识库版本更新与过期内容清理 (Priority: P2)

管理员上传新版资料（更新后的资质证书、新版方案模板、最新案例）时，指定其替代的旧版条目；系统将旧版标记为过期；证书按有效期到期自动标记过期。过期条目默认不参与 AI 检索与生成，避免新旧信息混用导致标书自相矛盾。

**Why this priority**: 保障生成内容正确性的机制性要求。初期可靠管理员人工维护勉强运行，但长期必须自动化，故列 P2 中的高位。

**Independent Test**: 上传新版营业执照替代旧版，随后生成标书，检查引用的是新版且旧版不再出现在检索结果中。

**Acceptance Scenarios**:

1. **Given** 知识库中已有旧版资质证书，**When** 上传新版并指定替代关系，**Then** 旧版状态变为「已过期」，默认不出现在检索结果与 AI 生成引用中。
2. **Given** 一张有效期截止于昨天的证书，**When** 系统执行到期检查，**Then** 该条目自动标记为过期，并通知知识库管理员。
3. **Given** 证书有效期距今 30 天内，**When** 系统执行到期检查，**Then** 向管理员发出到期提醒。
4. **Given** 存在过期条目，**When** 生成标书，**Then** 正文中引用过期资料的处数为 0；若无可替代的有效资料，系统以「重要」级别提示缺口而非静默使用过期资料。

### Edge Cases

- 招标文件为扫描件、照片或加密 PDF：无文字层时自动 OCR；加密/受保护文件给出明确失败原因与处理指引。
- 招标文件为压缩包，内含正文 + 多个附件（评分表、需求清单、格式模板）：需识别并合并解析，而非只解析首个文件。
- 评分标准表格跨页断裂、合并单元格、嵌套表格：提取时需保持评分项与分值的对应关系不错行。
- 招标文件中同一评分点在多处重复表述：合并去重，避免大纲重复响应。
- 招标文件内容与需求不匹配（例如上传的不是招标文件）：系统应识别并提示，而非产出无意义大纲。
- 超大文件（>200MB 或 >500 页）或超长生成任务：给出限制提示；生成中断（超时/网络/服务重启）后可从断点续跑，不丢失已生成章节。
- 知识库图片分辨率过低或含无关内容：插图前做可用性校验，低于阈值时不自动插入并提示人工选图。
- 智能插图无匹配素材：留占位符并在审核报告中提示「此处缺图」，不得凭空生成虚假现场图片。
- 证书已过期而招标文件要求该证书有效：审核以「致命」级别报出。
- 暗标场景下图片内嵌企业名称/Logo/水印：必须被识别处理，无法处理时阻断导出。
- 历史报价数据缺失某年度或字段缺失：分析结果需标注样本量与数据缺口，不得据此给出高置信度区间。
- 多人同时编辑同一份标书：需有并发编辑或加锁机制，避免互相覆盖。
- 招标文件对格式有强制要求（字号、行距、页边距、密封与签章位）：审核需按项目级配置检查，而非固定规则。

## Requirements *(mandatory)*

> 说明：每条功能需求（FR）下的「**验收标准**」为该条需求的可验证判定依据。除非另有说明，验收在**由 10 份真实招标文件 + 企业既有历史标书构成的验收样本集**上执行。

### Functional Requirements

#### A. 招标文件解读与大纲生成

- **FR-001**: 系统 MUST 支持上传并解析招标文件，格式包括 PDF、DOCX、DOC、图片扫描件与包含上述文件的压缩包；对无文字层的扫描件 MUST 自动执行 OCR。
  - **验收标准**：验收样本集 10 份文件 100% 解析成功并可按章节浏览；扫描件 OCR 后正文文字准确率 ≥95%（人工抽样 500 字校对）；解析失败时给出可读原因（加密/损坏/超限）。
- **FR-002**: 系统 MUST 提取投标人资格要求（营业执照、食品经营/生产许可、体系认证、业绩、财务、人员、设备等），逐条列出并标注原文出处（章节 + 页码）。
  - **验收标准**：与人工标注对比，资格条目召回率 ≥95%、准确率 ≥90%；每条均可跳转至原文位置。
- **FR-003**: 系统 MUST 提取评分标准并输出结构化评分表，字段含：评分项编号、评分项名称、分值、评分细则、原文定位。
  - **验收标准**：评分项召回率 ≥95%；分值合计与招标文件标称总分一致（或差异被明确报出）；跨页/合并单元格表格不错行。
- **FR-004**: 系统 MUST 提取废标、否决投标、无效投标条款并形成风险清单。
  - **验收标准**：废标条款召回率 ≥95%；每条含原文引用与「如何规避」的操作性建议。
- **FR-005**: 系统 MUST 输出政策与合规提示，指出本项目适用的投标政策要点与其对标书编制的影响。[NEEDS CLARIFICATION: 「自动解读最新投标政策」的范围——仅基于上传的招标文件 + 用户在知识库中维护的政策文件，还是需要系统联网抓取最新法规/政策并保持更新？]
  - **验收标准**：每条政策提示标注来源（文件名 + 条款），无来源的提示不得输出。
- **FR-006**: 系统 MUST 将 FR-002 的资格要求与知识库中的企业资质逐条比对，输出「满足 / 不满足 / 需补充」结论与缺口清单。
  - **验收标准**：在人工构造的 20 条资格要求（其中 5 条企业不满足）测试集中，「不满足」项识别率 100%，无漏报。
- **FR-007**: 系统 MUST 结合采购需求、评分标准与招标文件要求的响应顺序，自动生成多级标书目录大纲，且每个末级节点 MUST 关联其响应的评分项编号；未被覆盖的评分项 MUST 被显式列出。
  - **验收标准**：评分点大纲覆盖率 ≥98%；未覆盖项 100% 被列出；大纲层级与招标文件要求的章节顺序一致。
- **FR-008**: 用户 MUST 能对大纲进行增加、删除、重命名、拖动排序，并将大纲另存为模板供后续项目复用。
  - **验收标准**：编辑后刷新页面修改仍在；另存的模板可在新项目中被选用并完整还原层级。

#### B. 知识库管理

- **FR-009**: 系统 MUST 支持知识条目的批量录入，类型包括：资质证书、真实场景图片（冷库/车辆/检测现场/仓储分拣等）、历史标书与方案、项目案例、人员简历与证书、设备清单、报价记录、政策文件。
  - **验收标准**：单次批量上传 ≥30 个文件成功；部分失败不影响其余条目，失败项列出原因。
- **FR-010**: 系统 MUST 为每个知识条目维护元数据：业态（学校/医院/企业/机关/超市等）、区域、年份、项目类型、关键词标签、有效期、来源。
  - **验收标准**：元数据可编辑；缺少有效期的证书类条目在保存时被提示补充。
- **FR-011**: 系统 MUST 支持按业态、关键词、项目类型、年份检索知识库，并支持全文与语义检索。
  - **验收标准**：在 1000 条量级知识库中，检索响应 ≤3 秒；对 20 组人工设计的查询，Top-10 命中率 ≥90%。
- **FR-012**: 用户 MUST 能将检索到的历史方案「一键复用」到当前标书大纲的指定节点，文字与图片一并插入并保留来源标注。
  - **验收标准**：复用后目标节点内容与来源条目一致，来源可追溯。
- **FR-013**: 系统 MUST 支持知识条目的增、删、改、查，并按角色控制操作权限。
  - **验收标准**：无权限角色执行删除/修改被拒绝并记入日志。
- **FR-014**: 系统 MUST 支持版本替代与过期机制：上传新版资料时可指定被替代的旧版条目，旧版自动标记为过期；证书按有效期自动过期；过期条目默认不参与 AI 检索与内容生成。
  - **验收标准**：替代后旧版不出现在默认检索结果中；生成的标书引用过期条目处数为 0。
- **FR-015**: 系统 MUST 在证书有效期届满前 30 天向知识库管理员发出到期提醒。
  - **验收标准**：构造有效期为 T+29 天的证书，系统在当日提醒列表中包含该条目。
- **FR-016**: 系统 MUST 为生成内容提供引用溯源：正文任一由知识库素材生成的段落/图片可追溯到具体知识条目。
  - **验收标准**：随机抽取 20 处生成内容，均可查到来源条目 ID 与文件名。

#### C. 内容生成与图文排版

- **FR-017**: 系统 MUST 按大纲逐节生成标书正文，逐条响应评分点，并在节标题或章节属性中标注所响应的评分项编号。
  - **验收标准**：抽查 20 个末级节点，评分项标注与大纲一致率 100%；生成正文不含未替换的占位符。
- **FR-018**: 系统 MUST 根据段落语义从知识库匹配企业真实场景图片并插入对应段落，实现图文并茂。
  - **验收标准**：抽查 30 处插图，图文相关性人工评定合格率 ≥85%；无匹配素材时插入占位提示而非无关图片。
- **FR-019**: 系统 MUST 支持图片标注：在图片上对重点区域绘制高亮框（如红框），并在图片旁生成带边框的说明框（含加粗标题与说明正文），以及在图片下方生成名称题注（如设备名称、证书名称）。
  - **验收标准**：输出版式与需求文档样例截图一致（图 + 右侧带框说明 / 图 + 下方题注）；标注框位置、说明文字可由用户编辑；导出 Word 后标注不丢失、不偏移。
- **FR-020**: 系统 MUST 支持证书图片的表格式排版：每行 N 张证书图片，紧邻下方为对应的题注单元格（如「示例市龙头企业 / 放心消费示范单位 / 企业荣誉」），N 可配置。
  - **验收标准**：给定 3 张证书生成 3 列 1 行图 + 1 行题注的表格，与样例截图版式一致；图片等比缩放不变形；导出 Word 后表格边框与对齐保持。
- **FR-021**: 系统 MUST 根据正文语义自动生成简洁表格，至少覆盖对比表、进度表、配置表三类，并支持选择表格样式模板。
  - **验收标准**：给定含可结构化信息的 10 个段落，自动生成表格且表头与行项与正文数据一致率 ≥90%；用户可在生成后编辑单元格。
- **FR-022**: 系统 MUST 根据方案内容自动生成流程图与思维导图，并插入正文对应位置。
  - **验收标准**：生成的图形节点与正文步骤一一对应；导出 Word 后为清晰可读的图片或矢量图。
- **FR-023**: 系统 MUST 按招标文件要求生成合理化的网点分布图与车辆配送路线规划图。[NEEDS CLARIFICATION: 是否需要基于真实地图底图与地理编码（接入地图服务、按真实道路规划路线），还是生成示意性/结构化图示即可满足评标需要？]
  - **验收标准**：图中标注配送中心、网点、覆盖范围与路线分组，含图例；路线说明（车辆数、点位数、预计时长）与标书正文时效承诺一致。
- **FR-024**: 系统 MUST 支持将标书导出为 Word（.docx）与 PDF，保留标题层级、自动目录、页眉页脚、图表自动编号与图片质量。
  - **验收标准**：导出的 .docx 在 Microsoft Word 中打开无格式错乱；目录页码与正文一致；图片 DPI ≥150；100 页文档导出耗时 ≤2 分钟。

#### D. 审核与内容优化

- **FR-025**: 系统 MUST 对标书执行智能审核，检查项至少包括：资质齐全性、废标条款规避、评分点逐条响应覆盖、格式规范（字体、字号、行距、页码、目录、签署盖章位、密封要求）。
  - **验收标准**：在人工注入 20 处缺陷（含 5 处缺失资质、5 处未响应评分点、5 处触发废标条款、5 处格式违规）的测试标书中，检出率 100%；误报率 ≤20%。
- **FR-026**: 系统 MUST 输出审核报告，每条问题含严重级别（致命/重要/提示）、问题描述、定位、原因（引用招标文件原文）、修改建议，并支持一键跳转至问题位置。
  - **验收标准**：报告可导出；点击任一问题跳转定位准确；修复后重新审核该问题消失。
- **FR-027**: 系统 MUST 支持对用户上传的已完成标书进行「无损内容提升」：在不改动原有格式与标题层级的前提下，对正文进行润色、补充、数据更新与表达优化，并提供修订对照供逐条接受/拒绝。
  - **验收标准**：用文档比对工具确认样式、标题层级、编号、页眉页脚、页面设置与原文档差异为 0；修订对照可逐条接受/拒绝并生效。
- **FR-028**: 系统 MUST 对合同、发票等关键信息进行识别与标注（金额、期限、签约主体、发票号、开票日期等）。
  - **验收标准**：给定 10 份合同/发票，关键字段识别准确率 ≥90%，标注可人工修正。
- **FR-029**: 系统 MUST 管理佐证截图：信用信息、人员证书、体系认证证书的网上查询截图，以及发票/转账证明的税务局联网查询截图，并将其归档、匹配到对应资质/发票条目、插入标书对应位置并附题注。[NEEDS CLARIFICATION: 佐证截图由系统自动联网查询并抓取（需对接信用中国、税务、认证机构等外部查询页面），还是由用户人工查询后上传截图、系统仅负责归档、匹配与自动插入？]
  - **验收标准**：每张佐证截图与其对应的资质/发票条目建立关联；插入标书后位置正确、题注正确、可追溯来源与截图日期。
- **FR-030**: 系统 MUST 支持暗标生成：输出图文并茂的脱敏版标书，自动移除或替换企业名称（「示例公司」及配置的关联词）、品牌、Logo、水印、网址、人员姓名、可识别地址等身份信息；脱敏词典可维护，处理结果可人工确认。
  - **验收标准**：暗标输出中脱敏词命中数为 0；图文要素完整度与正常标书一致（图片、表格、图示数量不减少）。
- **FR-031**: 系统 MUST 在暗标生成后执行残留识别信息扫描，覆盖正文、页眉页脚、图注、表格及图片内文字，输出残留报告；存在未确认残留时 MUST 阻断导出。
  - **验收标准**：对含 10 处隐藏标识（其中 3 处位于图片内）的测试标书，检出率 100%；存在残留时导出被阻断并给出处理入口。

#### E. 数据分析与演示输出

- **FR-032**: 系统 MUST 支持历史报价数据的导入与结构化存储，字段至少包括：项目名称、时间、区域、平台、业态、品类、报价、中标价/中标与否。
  - **验收标准**：Excel/CSV 导入可配置字段映射；导入结果报告含成功/失败条数与失败原因。
- **FR-033**: 系统 MUST 支持按时间、区域、平台、业态（学校/医院/企业等）多维度组合筛选并输出报价对比图表与统计指标（均价、最高/最低、中标价区间、样本数）。
  - **验收标准**：任意维度组合筛选结果与原始数据人工核算一致；样本数不足（<5）时明确标注「样本不足，仅供参考」。
- **FR-034**: 系统 MUST 基于历史数据为当前项目给出参考报价区间及其依据（参考项目清单与筛选条件），并明确标注最终报价由人工决定。
  - **验收标准**：每个参考区间均可展开查看其依据项目清单；界面含免责声明文案。
- **FR-035**: 系统 MUST 根据投标方案核心内容自动生成述标/答辩 PPT，含关键图表、服务亮点、团队介绍，支持模板选择，并导出 .pptx。
  - **验收标准**：生成耗时 ≤5 分钟；页数 15–25 页；导出的 .pptx 在 Microsoft PowerPoint 中打开无排版错乱、文字不溢出版心；内容与标书事实一致（抽查 20 条数据点，一致率 100%）。
- **FR-036**: 系统 MUST 维持 PPT 与标书的一致性：标书更新后可一键同步刷新 PPT 中引用自标书的内容，用户已自定义修改的页面给出冲突提示而非静默覆盖。
  - **验收标准**：修改标书中的一项数据后同步刷新，PPT 对应页数据同步更新；被用户改过的页触发冲突提示。

#### F. 项目管理、安全与交付

- **FR-037**: 系统 MUST 以「投标项目」为工作台组织资料，统一管理该项目下的招标文件、解读结果、大纲、标书、审核报告、暗标、PPT 及其版本历史。
  - **验收标准**：可查看并回滚到任一历史版本；版本含创建人与时间。
- **FR-038**: 系统 MUST 使长时生成任务可控：进度实时可见，可暂停、续跑、重生成单个章节；任务中断后可从断点恢复且不丢失已生成内容。
  - **验收标准**：在生成过程中强制中断服务后重启，已生成章节完整保留并可续跑。
- **FR-039**: 系统 MUST 提供基于角色的权限控制与操作审计日志（登录、上传、导出、删除、脱敏确认等）。
  - **验收标准**：越权操作被拒绝并记入日志；日志可按用户/时间/操作类型检索。
- **FR-040**: 系统 MUST 保证企业资料的访问受控：知识库与项目资料仅授权用户可访问，所有导出操作 MUST 被记录。
  - **验收标准**：未授权账号无法读取任一知识条目或项目；导出记录含用户、时间、文件。
- **FR-041**: 系统 MUST 提供模型使用培训材料与 1 个月试用期的评估记录（试用期内的使用量、生成量、问题反馈与处理），作为验收判断依据。
  - **验收标准**：交付培训文档与操作手册；试用期结束时可导出评估报告。

### Key Entities

- **投标项目（Bid Project）**：一次投标活动的容器。属性：项目名称、采购人、业态、区域、投标截止时间、状态；关联招标文件、大纲、标书、审核报告、PPT。
- **招标文件（Tender Document）**：上传的原始文件及其解析结果。属性：文件、格式、页数、是否 OCR、解析状态。
- **资格要求（Qualification Requirement）**：从招标文件提取的一条投标人资格门槛。属性：描述、原文定位、匹配结论（满足/不满足/需补充）。
- **评分项（Scoring Item）**：一条评分标准。属性：编号、名称、分值、评分细则、原文定位、被响应的标书节点。
- **废标条款（Disqualification Clause）**：一条否决性条款。属性：描述、原文定位、规避建议、规避状态。
- **标书大纲节点（Outline Node）**：多级目录中的一个节点。属性：层级、标题、顺序、关联评分项、内容生成状态。
- **标书章节（Proposal Section）**：一个大纲节点对应的正文内容。属性：正文、插图、表格、图示、引用来源。
- **知识条目（Knowledge Item）**：知识库中的一份素材。属性：类型、文件、标题、业态、区域、年份、项目类型、标签、有效期、版本、状态（有效/过期）、被替代关系。
- **图片标注（Image Annotation）**：附加在图片上的标注。属性：标注区域（高亮框坐标）、说明框标题与正文、题注文字。
- **表格块（Table Block）**：自动生成的表格。属性：类型（对比/进度/配置）、表头、行数据、样式模板、来源段落。
- **审核问题（Audit Finding）**：一条审核发现。属性：类别、严重级别、描述、定位、原文依据、修改建议、状态（未处理/已修复/已忽略）。
- **脱敏规则（Redaction Rule）**：暗标脱敏词与替换策略。属性：原词/正则、替换文本、适用范围（正文/图注/图片内文字）。
- **报价记录（Quotation Record）**：一条历史报价。属性：项目、时间、区域、平台、业态、品类、报价、中标价、结果。
- **演示文稿（Presentation）**：生成的答辩 PPT。属性：模板、页面、引用的标书章节、同步状态。
- **用户与角色（User / Role）**：账号及其权限集合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 投标专员上传一份 ≤300 页的招标文件后，可在 **10 分钟内**获得资质门槛清单、评分标准表、废标风险清单与可编辑的标书大纲。
- **SC-002**: 在 10 份真实招标文件构成的验收样本集上，评分项与废标条款的提取**召回率 ≥95%**（以人工标注为基准），且每条可定位到原文。
- **SC-003**: 一份完整技术标的首版成稿时间由现状的**平均 3 个工作日缩短至 4 小时以内**，其中系统自动生成的内容占比 **≥80%**。
- **SC-004**: 在人工注入 20 处缺陷的测试标书上，智能审核对「缺失必需资质」与「评分点未响应」两类问题的**检出率为 100%**，整体误报率 ≤20%。
- **SC-005**: 暗标输出中出现企业名称、品牌、Logo、水印等可识别信息的**处数为 0**（覆盖正文、页眉页脚、图注、表格与图片内文字）。
- **SC-006**: 答辩 PPT 在 **5 分钟内**生成，页数 15–25 页，用户为达到可上台使用状态所需的人工改动量 **≤20% 的页面**。
- **SC-007**: 证书图片题注表格与图片重点标注（红框 + 右侧说明框）的一次生成版式正确率 **≥90%**，导出 Word 后无偏移、无丢失。
- **SC-008**: 知识库中新版资料上传后，新生成标书引用过期资料的**处数为 0**。
- **SC-009**: 1 个月试用期内，投标专员可**独立完成至少 3 个真实项目的完整流程**（解读 → 大纲 → 生成 → 审核 → 导出 → PPT），无需开发人员现场介入。
- **SC-010**: 试用期结束时，目标用户对「是否愿意在下一次投标中继续使用本系统」的肯定回答比例 **≥80%**。

## Out of Scope（系统不做的范围）

以下内容在本期**明确不做**，如后续需要须另行立项：

**投标流程边界**

1. **不对接电子招投标平台**：不自动登录采购平台、不自动下载招标文件、不自动上传或递交投标文件。
2. **不生成平台专用加密投标文件包**（如各地交易中心「投标文件制作工具」产出的专有格式）。最终格式转换与递交由人工在平台工具中完成。
3. **不提供电子签章 / CA 数字证书签署**，也不代替人工加盖公章、法人章。
4. **不做招标商机采集与推荐**：不爬取招标公告网站、不做项目线索推送。
5. **不做投标决策**：是否投标、最终报价数字由人工决定，系统仅提供分析与建议。

**内容边界**

6. **不生成或伪造任何佐证材料**：不生成虚假资质证书、虚假业绩合同、虚假检测报告、虚假现场照片。缺素材时只能报缺口。
7. **不做法律意见与合规裁定**：政策与废标条款提示仅为编标参考，不构成法律意见。
8. **不承诺中标**，也不预测中标概率。
9. **不支持外文标书**：本期仅支持简体中文招标文件与标书。
10. **不做商务标 / 报价清单的自动填报**：报价明细表、工程量清单等的逐行填报不在本期范围（仅做历史报价分析与参考区间）。

**系统边界**

11. **不做通用办公文档协同平台**：不替代企业网盘、OA、即时通讯。
12. **不做食材配送业务系统**：不含订单、采购、库存、配送调度、结算、追溯等 ERP/供应链功能。
13. **不做对外销售的多租户 SaaS 版本**：本期为单企业内部使用，跨企业数据隔离、计费、开放 API 不在范围内。
14. **不做移动端原生 App**：本期为浏览器端使用；移动端仅需页面可查看，不保证完整编辑体验。
15. **不做训练自有大模型**：本期使用现成模型能力 + 企业知识库，不含模型预训练/微调工程（如后续需要另行评估）。
16. **不替代人工终审**：任何标书在递交前仍需人工复核并签字确认，系统不提供「免审直接递交」路径。

## Assumptions

- **使用主体**：示例配送（食材配送企业）内部投标团队，单企业、多用户；用户为业务人员，无需技术背景即可操作。
- **交付形态**：浏览器访问的 Web 应用；标书导出 Word(.docx) 与 PDF，演示文稿导出 PowerPoint(.pptx)。
- **语言**：简体中文。
- **招标文件来源**：由用户手工下载后上传，系统不主动获取。
- **历史报价数据来源**：由用户以 Excel/CSV 导入，或从已入库的历史标书中提取后人工确认；系统不接入外部价格数据源。
- **知识库初始数据**：由企业提供真实资质证书、场景图片（冷库/车辆/检测现场/仓储分拣）、历史标书与方案、案例、人员与设备资料；系统上线前完成首批导入。
- **暗标脱敏词**：以「示例公司」及其关联词（企业全称、简称、品牌、母公司、网址、商标、常用人员姓名）为初始词典，由用户在系统中维护扩充。
- **「无损」的定义**：文档的样式、标题层级、编号、页眉页脚、页面设置保持不变，仅正文文字内容发生变化。
- **格式规范检查**：以项目级可配置规则执行（不同招标文件对字体、字号、行距、密封与签章的要求不同），而非固定的全局规则。
- **AI 生成内容需人工确认**：所有生成结果均视为初稿；涉及数据、承诺、资质的内容以知识库中的真实资料为唯一事实来源，系统不得凭空编造。
- **验收基准数据**：由业务方提供 10 份真实招标文件与对应的人工标注结果，作为提取类需求（FR-002/003/004）召回率与准确率的评判基准。
- **验收方式**：按需求清单第 5 条，提供模型使用培训并以 **1 个月试用期**的实际使用效果作为最终判断依据。
- **并发规模**：同时在线用户 ≤20 人，同时进行的长文档生成任务 ≤5 个。
